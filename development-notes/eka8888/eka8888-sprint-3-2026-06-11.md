# Sprint 3: Directives, Pipes & Forms



## What was done

During Sprint 3, I focused on the authentication and user profile parts of our ShopFront application. My main goal was to replace simple template inputs with Angular Reactive Forms and improve the overall structure of the authentication flow.

The main feature components I worked on were:

### 1. Login Page

I rebuilt the Login page using Reactive Forms and FormBuilder. The form contains email and password fields with validation rules. For the email field I used Angular's built-in email validator, and for the password field I used the required validator.

I also integrated the form with our Auth service and implemented navigation after successful login. Since we are not using the real commercetools API yet, the login process currently works with a mock authentication service and local storage.

Angular concepts used:

* Reactive Forms
* FormBuilder
* Validators
* Dependency Injection
* Signals
* OnPush Change Detection
* Router navigation

### 2. Registration Page

I implemented a larger registration form containing:

* First Name
* Last Name
* Email
* Password
* Date of Birth
* Street
* City
* Postal Code
* Country

The most interesting part was creating validation rules. Besides Angular built-in validators, I created and integrated a custom password validator that checks whether the password contains both letters and numbers.

Angular concepts used:

* Reactive Forms
* Custom ValidatorFn
* Form validation
* Dependency Injection
* Shared reusable components
* OnPush Change Detection

### 3. Profile Page

I redesigned the Profile page and converted it into a Reactive Form. The page displays personal user information and a mock address section that will later be connected to the commercetools Customer API.

The profile currently supports editing user information and demonstrates how profile data can be updated in the future.

Angular concepts used:

* Reactive Forms
* Form validation
* Shared form components
* Signals
* OnPush Change Detection


## What I Learned

This sprint significantly improved my understanding of Angular forms and dependency injection.

Key lessons learned:

* Reactive Forms are much easier to maintain than template-driven forms for complex forms.
* ControlValueAccessor is essential when creating reusable form components.
* Signals work very well together with OnPush Change Detection.
* Custom validators provide a clean way to encapsulate business rules.
* Shared UI components reduce duplication and improve consistency across pages.
* I learned how Angular's InjectionToken can be used to inject configuration values and non-class dependencies through Angular's Dependency Injection system.
* I gained a better understanding of Angular providers, especially the useValue provider configuration.

## Challenges

One of the main challenges during this sprint was learning Angular's advanced Dependency Injection features. Before this sprint I had never worked with InjectionToken and initially found it difficult to understand why it was needed when services could already be injected.

After implementing an APP_CONFIG InjectionToken with a useValue provider, I understood how Angular can inject configuration objects and non-class dependencies in a type-safe way. This helped me better understand Angular's Dependency Injection system and provider configuration.

Another challenge was working with custom form validation and integrating validation messages into reusable form components while keeping the templates clean and maintainable.
